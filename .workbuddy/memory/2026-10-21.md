# 2026-10-21

## Node 版本升级（22 → 26）

### 版本决策依据（nodejs/Release schedule.json）

| 版本 | 状态 | 关键日期 |
|---|---|---|
| v26 | Current → **2026-10-28 转 Active LTS** | EOL 2029-04-30 |
| v24 | **2026-10-20 刚转 Maintenance** | EOL 2028-04-30 |
| v22 | Maintenance（原 CI 版本） | EOL 2027-04-30 |
| v20 | 已 EOL | 2026-04-30 |
| v18 | 已 EOL | 2025-04-30 |

**结论**：v24 昨天刚退居维护期、v26 一周后转正，所以直接上 26 而非 24。

### 已完成（项目侧）

**blog** `eedfb7c`
- `deploy-from-source.yml`：`node-version` 22 → **26**
- `package.json`：新增 `engines.node: ">=26"`（此前无 engines）
- CI 实测 run `39626904634` **success**，日志确认 `Acquiring 26.12.0`，
  引擎告警 0 条、action 弃用警告 0 条

**Panda** `2b909c7`
- `engines.node`: `>=18` → **`>=22`**
- **刻意不设 26**：Panda 发布在 npm，engines 是对所有使用者的约束，
  强制 >=26 会让 22/24 LTS 用户装不上。选 22 是因为它是当前仍受支持的
  最旧 LTS 线（18/20 均已 EOL，继续声明等于承诺支持死版本）。
- **注意**：这是元数据变更，**需下次 npm publish 才对外生效**。

### 兼容性实测（用官方 win-x64 包本地跑，两个版本都过）

- Node 24.22.1 与 26.12.1 均能 `hexo generate` 成功
- verify-feed 58 条目 link/id 唯一、38 条碎碎念路径式地址
- **`@resvg/resvg-js` 原生绑定在两个版本下都能加载并渲染**（N-API ABI 稳定，
  这是升大版本最常卡的地方，已排除）
- Panda 测试 52/52 在两个版本下均通过
- hexo 8.1.2 要求 `node>=20.19.0`；resvg engines `>=10` —— 均无阻塞
